# Заметки по разработке

История решений и грабли, чтобы не наступать дважды.

## Как всё началось

Цель — голосовое управление JAC JS3 через Алису. У сигнализации «Цезарь Сателлит»
(Cesar Smart) нет ни публичного API, ни навыка для Алисы. Путь:

1. Разобрали APK `Cesar Smart` (`ru.csat.sdk`), нашли внутренние эндпоинты и OAuth-клиент.
2. Собрали CLI `tools/cesar_api.py` и проверили команды на живой машине.
3. Написали интеграцию `custom_components/cesar_smart` (координатор, 8 платформ).
4. Вывели авто в Яндекс Smart Home (форк YSH, облако yaha-cloud).

## Грабли

### Авторизация
- Access-токен жив **120 секунд** — нужен refresh перед каждым «холодным» запросом.
- Refresh-токен при обновлении может меняться — сохраняйте новый.
- При входе по паролю телефон надо пробовать в трёх форматах (`+7…`, `8…`, цифры):
  какой именно ждёт сервер, заранее не угадать.

### Команды и статусы
- Все статусы приходят **строками** (`"FUEL_VALUE": "67.0"`) — приводите типы.
- `CAR_LOCK=CLOSED` = **заперто** (не наоборот).
- `BOOT_CLOSE` в API нет: багажник только открывается. Команда «закрыть» вернёт
  `ServiceNotSupported` в HA (в Алисе — ошибка).
- Набор команд зависит от комплектации: стройте кнопки из `getUnitAvailableCommand`,
  а не из фиксированного списка.
- После команды состояние в облаке обновляется не сразу: опрос через 8–18 с.

### Home Assistant
- `ConfigEntry.runtime_data` — современный способ; на старых HA не заработает.
- Одна HA-сущность = одно устройство в УДЯ (YSH `device_id = entity_id`).
- `_attr_has_entity_name = True` + `device_info` даёт имена вида
  «JAC JS3 · Замок». `entity_id` при переименовании не меняется.
- Неиспользуемые сущности после удаления кода остаются в реестре как `unavailable` —
  удаляйте через WebSocket `config/entity_registry/remove`.

### Яндекс Smart Home
- `entity_config` читается **только из `configuration.yaml`**.
- `devices.types.openable.door_lock` УДЯ не принимает → используйте `openable`.
- `include_entities` живут в `.storage/core.config_entries` →
  `options.filter.include_entities`; WebSocket-команда обновления опций недоступна.
- Кириллица в именах — обязательна для ручного ввода в приложении «Дом с Алисой».

### Кодировки (Windows + PowerShell)
- Кириллицу в файлы писать только `[IO.File]::WriteAllText` с
  `New-Object Text.UTF8Encoding($false)`; `Set-Content`/`Get-Content` в PS 5.1 портят.
- Вывод консоли может показывать кракозябры — проверяйте байты (hex), а не глаз.

## Структура

```
custom_components/cesar_smart/
├── __init__.py      # setup/unload, PLATFORMS
├── api.py           # OAuth, запросы, gather_unit
├── coordinator.py   # DataUpdateCoordinator, CesarUnit, опрос раз в 120 с
├── entity.py        # базовая сущность + device_info
├── config_flow.py   # вход по телефону/паролю или refresh-токену
├── const.py         # URL, заголовки, коды команд
├── switch.py        # двигатель, охрана
├── lock.py          # центральный замок
├── cover.py         # багажник (только open)
├── binary_sensor.py # двери, зажигание, охрана, замки, автозапуск
├── sensor.py        # топливо, пробег, температуры, АКБ, балансы, скорость
├── device_tracker.py# GPS
├── image.py         # картинка авто (car.png)
├── button.py        # сигнал, свет, поиск, сервисный режим, обновление
└── brand/, translations/
```

## Идеи на будущее

- `BOOT_CLOSE` — уточнить в поддержке, есть ли команда у других моделей сигнализаций.
- Капот/датчик удара — если появятся в статусах.
- Локальный (BLE) канал вместо облака — в приложении есть `BLE_NUMBER`, но протокол не разобран.
- Опрос по событию: `getExecutingCommands` уже запрашивается, можно уменьшить интервал
  после команд.
